## 二、需求演进（三次修正）

**① 原始方案**（来自 Obsidian 方案笔记）
草稿输入 → AI 生成电视稿/报刊稿 → 人工审定 → 多平台新媒体稿 → **API 推送到各平台** → 人工审核发布

**② 技术选型验证后的三项修正**
| 原方案 | 修正为 | 原因 |
|---|---|---|
| Claude + GPT-4o 多模型混合 | **统一 DeepSeek** | Claude/OpenAI 官方 API 未对中国大陆开放；DeepSeek 中文新闻改写性价比高 |
| API 推送到各平台后台 | **生成最终成稿 + 人工复制粘贴发布** | 小红书无公开发布 API、微信公众号需认证、抖音需企业资质；混合方案不可维护 |
| Docker 自部署 | **宝塔面板直接部署** | 服务器已装宝塔，且 80 端口有系统 Nginx 在跑既有站点 |

**③ 使用过程中迭加的功能**
AI 审稿节点 → 节点级提示词编辑 → 工具节点（稿件精简 / 风格提取）→ 界面品牌与交互优化（可拖拽调宽、节点库视觉区分）

## 四、关键设计决策（含理由）

1. **不做平台直推，改"成稿导出 + 人工粘贴"**
   调研确认小红书无公开第三方发布 API，微信需认证服务号、抖音需企业资质。改为生成最终成稿（来源稿预览 → 一键复制全文 → 下载 .md），把不可控的平台对接风险降到最低。

2. **无 API Key 时自动"模拟模式"**
   未配置 `DEEPSEEK_API_KEY` 时返回带「模拟模式」标注的版式化文本，保证流程可演示、可自动化测试；配置后自动切换真模型（实测无缝切换）。

3. **稿件内容池解析规则：直接上游优先 → 空则传递回溯**
   审定/AI 审稿节点本身不产出稿件，若只取直接上游会取不到内容。规则改为：先取直接上游；若直接上游无稿件，沿边向更上游回溯。

4. **风格提取产物做"元数据隔离"**
   风格提取节点输出 `format_type=style_prompt`，被审稿、成稿导出、内容池自动排除，不会被当成稿件处理；同时若它连到改写节点，其内容会作为「参考风格要求」注入下游提示词。

5. **AI 审稿默认"标准模式"而非严格模式**
   早期标尺过严，把一份正常稿以"标题与正文年份矛盾"为由打回（实为误判）。改为只对事实矛盾、夸大失实、敏感违规、严重语病等实质问题打回；重要稿件可开"严格模式"（评分<80 即打回）。

6. **精简节点做"二次强制压缩"**
   DeepSeek 首轮普遍删得不够（要求压到 1/3，实测只到 69%）。改为：首轮结果若超出目标字数 1.15 倍，则按明确字数上限再压（最多 2 次），并提供 1/4、1/3、1/2 三档，后端默认 0.35。

7. **节点级配置化**
   提示词、模型档位（deepseek-chat / deepseek-reasoner）、审稿严格模式、精简压缩比，全部存入节点 `config`（JSONB），做到"同类型节点可各不相同"。

## 五、最终功能清单

**画布与节点（7 类）**
- 草稿输入 · AI 改写（TV/报刊）· 人工审定 · 🤖 AI 审稿 · 新媒体转换（公众号/微博/抖音/小红书/头条）· 🧰 工具（稿件精简 / 风格提取）· 成稿导出（5 平台）

**执行与协作**
- 按连线拓扑执行；单节点执行 + 整画布"自动执行"（跳过需人工的审定节点）
- WebSocket 实时推送节点状态（待命/执行中/完成/失败/已通过），画布节点与连线动态着色
- 标准工作流模板一键生成（10 节点 10 连线），也可建空白项目自由拖拽连线
- 稿件 Revision 追溯链（parent_revision_id）+ 节点历史

**审稿**
- 人工审定：逐篇批注 / 通过 / 打回
- AI 审稿：自动判定 + 写回 `[AI审稿·模型] 意见（评分 xx·标准/严格）`；新建项目可勾选默认替换人工审定

**成稿与发布**
- 成稿导出节点：来源稿选择（点击即预览）、字数统计、一键复制全文、下载 .md
- 全程不调用任何平台 API，由用户复制后到平台后台发布

**界面**
- 三栏结构：左侧节点库（分组色点 + 条目色带 + 终稿徽标）· 中部无限画布 · 右侧配置面板（可拖拽调宽 260–780px，宽度记忆，双击复位）

## 六、踩坑与修复记录（有复用价值）

| # | 问题现象 | 根因 | 修复 |
|---|---|---|---|
| 1 | 前端构建报 `csstype/index.d.ts TS1005` | 首次 `npm install` 中断，类型文件被截断（19517 行处报 19518 行错） | `rm -rf node_modules` 干净重装 |
| 2 | `ReactFlow` 报 TS2786 无法作为 JSX 组件 | `@xyflow/react` v12 **无默认导出**，默认导入绑定到了模块对象 | 改为命名导入 `import { ReactFlow }` |
| 3 | systemd 服务反复 `activating` | 冒烟测试残留的 uvicorn 进程占着 8000 端口 | 清理残留进程后重启服务 |
| 4 | `sudo` 一直认证失败 | `echo 密码 \| sudo tee 文件 <<EOF`：**管道与 heredoc 争抢 stdin**，密码没送达 | 改为"先写临时文件 → `sudo cp`" |
| 5 | 转换节点报"缺少上游稿件内容" | 审稿节点不产稿，直接上游取不到内容 | 上游解析改为**传递性回溯** |
| 6 | 导出的成稿来源是报刊稿而非公众号稿 | 选稿规则偏好"最深处已审定稿"，忽略了直接上游 | 改为**直接上游优先**，空才回溯 |
| 7 | 成稿预览生成后被清空 | 生成后调用来源刷新，刷新函数里把预览状态一并重置 | 仅切换节点时重置；按 revision_id 回查服务端 |
| 8 | 提示词"已保存"提示一闪而没 | 同类问题：`syncNode` 触发 effect 又把 `saved` 置 false | 从刷新 effect 中移除该重置 |
| 9 | E2E 断言"假通过" | 提示词输入框与输出预览用了同一个 class，`querySelector` 选错元素 | 拆分为 `.out-content` / `.preview-content` |
| 10 | AI 审稿误打回正常稿 | 审稿提示词标尺过严（把"未写年份"当重大问题） | 务实化提示词 + 标准/严格双模式 |
| 11 | "夸大稿被 AI 审稿放行" | 实为**改写环节已清理夸大内容**，审稿对象是干净稿 → 非漏检 | 通过对比改写前后文确认，无需改代码 |
| 12 | 精简幅度不达标（要求 1/3 只到 69%） | 模型不愿删事实；且未点档位时后端无目标值 | 二次强制压缩 + 档位 + 后端默认 0.35 |
| 13 | 测试中节点"重叠"点不到 | 画布 fitView 放大 1.9 倍，卡片视觉变大后相邻（并非布局 bug） | 脚本改为先归位节点/适应视图再操作 |
| 14 | 无头浏览器读不到剪贴板 | Chromium 无头环境限制 readText（写入成功，toast 已证实） | 断言改为验证写入反馈 |

## 十、经验小结

1. **先核实、再动手**：服务器现状（宝塔/端口/已有站点）、第三方库的导出方式（xyflow v12）都靠实测确认，避免按印象编码。
2. **自动化 E2E 是最大杠杆**：本轮 15 个脚本让每次功能迭加都能回归验证，也多次抓出"假通过"的断言缺陷。
3. **React 高频陷阱**：把"切换节点时重置"和"数据刷新后同步"混在一个 effect 里，会出现"刚设置就被清掉"的诡异现象（本项目犯了两次）。
4. **命令链别用 `| tail && echo OK`**：管道会吞掉退出码，导致构建失败仍显示成功。
5. **对 AI 输出的质量要设兜底**：提示词约束不足时（删减不够、标尺过严），用"二次压缩""双模式"等工程手段补位。

### 13.6 工具节点新增「PDF 版面提取」（提交 `f46de95`）

**用途**：把报纸/文件 PDF 里的稿件按**版面版块**提取出来，直接交给下游节点（AI 改写 / 审稿 / 新媒体转换）继续处理。

**操作流程**
1. 从节点库「工具」组拖入 **📄 PDF 版面提取** 节点
2. 面板点「上传 PDF 文件」（≤40MB，仅 PDF）
3. 系统自动解析并按版块列出：**第 N 版 · 第 X 栏 · 字数 · 识别到的标题 · 正文预览**
4. 勾选需要的版块（可全选/全不选，实时显示已选字数）→ 点「生成稿件」
5. 把该节点连到下游节点（改写/审稿/转换），稿件即作为输入流转

**解析引擎（`backend/app/pdf_tools.py`，PyMuPDF）**
- **合并相邻块**：同栏、同字号、纵向相邻的块合并（PDF 常把一行标题或一段正文拆成多个块）
- **正文字号判定**：取"按字数加权的众数字号"作为基准（比中位数稳——标题多时中位数会被带偏）；字号明显更大且较短的块判为**标题**
- **成稿规则**：按「页 → 栏 → 纵坐标」排序，标题块与其后同栏的正文块合并为一篇稿件
- **文本还原**：去掉中文之间因两端对齐产生的空格、按数字/标点边界续接被换行截断的句子

**接口**：`POST /nodes/{id}/pdf`（上传并解析）、`GET /nodes/{id}/pdf`（状态与版块）、`POST /nodes/{id}/pdf/select`（选用版块生成 Revision）、`DELETE /nodes/{id}/pdf`（移除）
**成本**：本地解析，**不调用 AI、不消耗配额**；生成的稿件状态为 rewritten，可正常参与下游流程
**清理**：删除节点或项目时自动清理上传目录（`uploads/` 已加入 .gitignore）

**边界处理（已实测）**
| 场景 | 响应 |
|---|---|
| 扫描图片版 PDF（无文字层） | 400「未从该 PDF 识别到文字（可能是扫描图片版）。需要 OCR 才能提取，请联系管理员。」 |
| 上传非 PDF 文件 | 400「只支持 PDF 文件」 |
| 未上传就执行节点 | 400「请先上传 PDF 文件并选择版块」 |

**实测结果**
- 后端：模拟报纸版面（两栏两篇）→ 正确识别 **2 篇**，标题为《云阳县融媒体中心开展防汛应急演练》《全县中小学开学第一课聚焦安全教育》，正文无断字
- 界面 9/9 通过：节点库出现 → 拖入画布 → 上传 → 解析摘要（1 页 / 271 字 / 2 版块）→ 版块列表 → 勾选计数联动 → 生成稿件 333 字 → 一键复制；0 控制台错误
- 下游联动：PDF 提取稿 → 公众号转换节点，正常输出 1676 字

**后续可选**：扫描版 OCR（tesseract / PaddleOCR）、多页报纸整版处理、版块顺序手工调整。

## 十四、稳定性强化：AI 重试与并发控制（提交 `8934216`、`cd8a6ad`）

**背景**：AI 调用此前没有重试也没有并发限制——DeepSeek 偶发超时/限流就让节点"莫名失败"；系统设置里的并发上限只有配置项、执行链路并未使用。

### 14.1 指数退避重试（覆盖所有 AI 调用）
统一收口在 `ai.py` 的 `_post_chat`（改写/转换/工具/审稿/排版导出全部经过它）：
- **3 次尝试**（1 次原始 + 2 次重试），退避 1s → 2s（带随机抖动），最大 8s
- **自动重试**：HTTP 429、5xx、请求超时、网络错误
- **不重试**：401/403（Key 无效）与其他 4xx，直接给出可操作提示
- **可读错误**：限流 / 超时 / 无法连接 / Key 无效，节点会显示真实原因（此前只显示"未知错误"）
- 用量记录新增 `retries` 字段，执行结果回传，界面提示里会显示"重试 N 次"

### 14.2 并发限制与排队（全局 + 单用户）
新增 `app/concurrency.py`：进程内并发限制器 + `ai_slot` 上下文管理器
- 读取系统设置：`max_concurrency_global`（默认 8）、`max_concurrency_user`（默认 2）、`max_queue_wait_seconds`（默认 120 秒）
- 超限时**排队等待**；排队超过 0.8 秒通过 WebSocket 推送 `queued` 状态 → 画布节点显示**「排队中」**（琥珀色）
- 排队超过上限 → 返回 429「AI 服务当前繁忙（已排队等待超过 N 秒），请稍后重试」，避免请求悬挂
- 管理后台「系统设置」可直接调整这三项

### 14.3 失败重试界面
节点执行失败时，配置面板显示红色提示条（含真实原因）+ **「↻ 重试执行」** 按钮，无需重新找节点/重新配置。

### 14.4 顺带修复的两个 bug
1. **失败原因丢失**：`HTTPException`（配额不足、缺上游、未上传 PDF 等）只回给前端，未写入节点记录，界面只能显示"未知错误" → 现已写入节点并推送
2. **配额无法清空**：管理接口把 `null` 当作"未提供"忽略，导致管理后台把配额输入框清空（想恢复"继承全局"）时实际不生效 → 改用 `model_fields_set` 判断显式传参

## 十五、运行台账：模板 × 用户 × 输入 × 生成物全链路留痕（提交 `ee0621c`）

**背景**：系统此前只有「AI 用量计数」和「审计日志」两类记录——前者只回答"谁烧了多少 token"，后者只回答"谁点了什么按钮"。真正的业务问题一个都答不了：**哪个模板被谁用过几次？他填了什么？AI 生成了什么？这次失败是配额拦的还是真出错了？** 这一节把这三件事补齐。

### 15.1 数据模型

| 变更 | 说明 |
|---|---|
| 新表 `run_logs` | 一次节点执行 = 一行；从"点下执行"到"拿到生成物"的全过程 |
| 新表 `template_versions` | 节点库/提示词模板每次改动留一份快照，台账里记的版本号能对上当时的原文 |
| 新列 `node_templates.version`、`prompt_templates.version` | 模板当前版本号（新建=v1，每次保存 +1） |
| 新列 `projects.template_key` | 画布来自哪个流程模板：`standard_v1` / `ai_review_v1` / `blank` |

`run_logs` 关键字段：

- **谁 / 何时 / 在哪**：`user_id` `username` `project_id` `project_name` `created_at`
- **跑了什么**：`node_id` `node_type` `node_subtype` `node_label` `node_template_id` `node_template_version`
- **怎么触发的**：`trigger` = `manual`（手动点） / `auto`（一键执行） / `retry`（失败后重试）
- **结果**：`status` = `ok` / `failed` / `blocked`（配额或排队拦截） / `running`，附 `error` 可读原因
- **输入输出**：`input_revision_id` `input_chars` `input_preview`（前 500 字）、`output_revision_id` `output_chars` `output_preview`（前 500 字）、`params`（参数快照 JSONB）
- **成本与性能**：`model` `prompt_tokens` `completion_tokens` `cost_est` `duration_ms` `retries` `queued_ms`
- **提示词溯源**：`prompt_source`（node 节点自定义 / global 全站模板 / builtin 系统内置）、`prompt_hash`（前 8 位 SHA-256，改没改一目了然）、`prompt_template_id` `prompt_template_version`

### 15.2 记录口径（拍板的"推荐默认"）

1. **成功、失败、被拦截全部入库**——只记成功会让"配额不够用""上游没连对"这类真实问题在报表里消失
2. **只存 500 字预览 + 参数快照**，不整篇存原文；正文仍以稿件版本（`revisions`）为唯一权威副本
3. **模板范围含版本化**：改模板不再是"黑箱覆盖"，而是 v1→v2→v3 可回溯
4. **仅管理员可见**：普通用户看不到台账接口（非管理员访问返回 401/403）
5. **删项目/删用户后保留统计、清空内容**：行不删，只把 `input_preview`、`output_preview`、`params` 清空，`project_id` 解绑但保留 `project_name`，因此"模板使用量、人均调用、成功率"等指标不会因为删项目而出现断层
6. **保留期 12 个月**，后台一键归档清理

### 15.3 埋点位置

全部收口在 `backend/app/routers/workflows.py > _run_node()`：

- 进入函数即建行（`status=running`），后台能看到"正在跑什么"
- `_run_input()` 在拿到上游稿件后写输入快照；`_pinfo = await _prompt_info(...)` 记录本次**实际生效**的提示词（节点自定义 > 全站模板 > 内置）
- `_finish_run()` 在 8 条返回路径（改写/转换、PDF 提取、AI 工具、人工审定 3 处、AI 审稿、导出直通、导出排版、草稿）收尾，写入生成物、模型、token、耗时、重试、排队
- 两个 `except` 分支收尾：`HTTPException 429` → `blocked`，其余 → `failed`
- 触发方式由调用方传入：手动执行接口读请求体 `trigger`，一键执行固定 `auto`，前端「↻ 重试执行」按钮传 `retry`
- `ai_reviewer` 一次审多篇，台账记 `input_chars` 为待审总字数、`output_preview` 为各篇结论汇总

### 15.7 踩坑记录

1. **`_run_node` 签名没改上，测试报 `TypeError: unexpected keyword argument 'trigger'`**：批量替换时锚点漏算了函数里的 docstring，替换静默失败（`str.replace` 不报错）。教训：脚本化改代码时每处替换都要 `assert count == 1`，本次其余 19 处都加了断言，唯独这一处早期漏加。
2. **`func.cast(...)` 在 PostgreSQL 不可用**：按天统计里想算"每天失败数"，写了 `func.sum(func.cast(cond, Integer))`，PG 的 `CAST` 是语法关键字而非函数，改为按 `(日期, 状态)` 分组后在 Python 里汇总。
3. **新表加了 `note` 列但迁移漏建**：模型加了字段、`CREATE TABLE IF NOT EXISTS` 对已存在的表不生效，必须补 `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`。幂等迁移清单是这类问题的唯一防线。
4. **`onClick={run}` 与 `run(isRetry)` 的隐式参数**：给函数加默认参数后，直接 `onClick={run}` 会把鼠标事件当第一个实参传入（真值）→ 每次手动点击都被记成"重试"。所有点击处统一改为 `onClick={() => run()}`。

### 16.3 修 BUG：切换节点时右侧提示词框仍显示上一个节点的提示词（提交 `2ed6b75`）

**现象**：在画布上依次点不同节点，右侧「🧠 提示词设置」里的内容有时不跟着变——比如点到「抖音」转换节点，框里却是「微博」节点的提示词。

**根因**（`Panels.tsx > PromptEditor`）：默认模板是**异步**载入的（`loadPromptDefaults()`），而初始化 effect 只用「默认模板有没有」当指纹：

```js
const key = `${node.id}|${defaultKey}|${defaultPrompt ? 1 : 0}`
if (!defaultPrompt || initRef.current === key) return
initRef.current = key
setDraft(cfg.prompt ? String(cfg.prompt) : defaultPrompt)   // ← 此刻 defaultPrompt 还是上一个格式的
```

切到另一个节点时，这个 effect 先拿着**上一个格式**的默认模板跑完、并记下了 key；等正确的默认模板到位后，effect 因为 key 没变而直接 `return`，于是框里永久留着上一个节点的提示词。另一种情况更糟：某个格式根本没有默认模板时 `defaultPrompt` 始终为空 → 初始化被整段跳过 → 同样残留上一个节点的内容。

**修复**：

1. 默认模板与它所属的 key 一起存 `def = { key, text }`，只有 `def.key === defaultKey` 才算本节点的默认值（跨格式的模板永远不参与）
2. 载入 effect 加 `alive` 标记，切走之后的异步结果直接丢弃（消除竞态）
3. 初始化改为「等当前格式的默认模板就位（**包括该格式确实没有默认模板**的情况）再填」，指纹简化为 `${node.id}|${defaultKey}`
4. 顺带：切节点时清空「我的模板」下拉选择

**验证**（Playwright，按 `data-id` 精确点击节点，覆盖 3 个项目 / 16 个带提示词的节点，逐个与 `/api/prompts` 的该格式默认值比对）：

| | 结果 |
|---|---|
| 修复前（同一套测试） | **11 处不跟随**（如 抖音节点显示微博提示词、TV 稿节点显示报刊提示词） |
| 修复后 | **0 处，RESULT: PASS**（16/16 节点提示词框内容与当前节点一致）；控制台 0 错误 |

> 附带收获：这次测试踩到两个测试自身的坑——① 用 `hasText: "微博"` 选节点会误中「微博成稿」，改成按 `data-id` 精确点击；② 曾用 `.includes(label)` 判断面板是否切过去了，改为比对面板标题的完整文本。测试脚本本身不严谨会让"修复效果"看起来时好时坏。

### 18.1 服务端：独立的本机 ASR 服务

| `/api/` 未设 `proxy_read_timeout`（默认 **60s**） | 长任务（深度思考模型、大文件上传）会被网关切断 | `proxy_read_timeout 900s` + `proxy_send_timeout 900s` |

### 18.5 踩坑记录

1. **首次推理慢到离谱（实时率 11.7）**：进程内 A/B 对比定位到"冷启动"——ONNX Runtime 首次推理要建内存池（3~6 秒），此前把冷启动算进了单段耗时。服务启动时预热两次静音后，实时率稳定在 0.10~0.12。
2. **PyAV 的 wav 编码器卡死**：写测试音频时 `pcm_s16le` 编码 4.5 分钟就挂住（CPU 95% 不返回），改用 Python 标准库 `wave` 写 wav、PyAV 只负责 m4a/mp3，问题消失（解码侧 PyAV 一切正常）。
3. **识别文本开头偶发孤立标点**（如 `.  朋友们…`）：`clean_text` 增加"整段只剩标点则丢弃、去掉开头孤立标点"。
4. **`<audio>` 播放器报 `ERR_FILE_NOT_FOUND`**：blob URL 在 `useEffect` 清理时立即 `revokeObjectURL`，而元素还挂着一帧旧地址。改为"新地址生成后延迟 3 秒再释放旧地址"，控制台归零。
5. **前端内置节点库兜底漏加新节点**：节点库优先用接口数据，但接口返回前（或离线时）用前端 `PALETTE` 兜底——新节点没加进去，表现为"刚登录时看不到 🎙️ 录音转文字"。已补齐。
6. **`pkill -f 关键字` 会杀掉自己的 ssh 会话**：远程命令行里含同一关键字，`pkill -f` 把自己也匹配掉了（进程清理改为按 PID）。

### 19.3 图标体系（规范第 7 章）

- 新增 `frontend/src/icons.tsx`：**Lucide** 线性图标，统一 1.75px 描边、currentColor、16/18/20 三档，随分类色着色

- 坑：`node_templates.icon` 原为 `VARCHAR(16)`，`message-square-text`（19 字符）写入直接导致**后端启动失败**——这正是自动化测试跑出来的；迁移里加宽到 40 并加了启动时幂等纠正（历史 emoji → Lucide 名）

### 19.4 顺带修掉的两个行为缺陷（都是新 UI 暴露出来的）

1. **顶栏永远显示「尚未运行」**：后端节点开始执行时会广播 `status: running`，而前端 WS 处理器把**任何**消息都当作"这个节点跑完了"并从运行列表移除 → 运行态瞬间被清空。改为只有终态（done/failed/approved/canceled）才移除。同时「运行工作流」改为前端按拓扑序逐个发起（`trigger=auto`），新增的「停止」因此能**真正中止后续节点**，顶栏可显示「运行中 3/9」。
2. **节点耗时被刷新覆盖**：`refreshCanvas` 用接口数据整体替换节点，而接口不返回耗时/字数 → 本地指标被清空。改为刷新时按节点 id 保留本地指标。
