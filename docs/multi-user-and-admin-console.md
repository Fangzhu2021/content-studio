# 内容工坊 · 多人使用与管理后台方案（设计稿 v1）

> 日期：2026-09-09 　状态：待评审 　配套：[[内容工坊 - 在线无限画布稿件改写系统]]

## 1. 目标

把系统从"单人/小范围试用"升级为**融媒体中心内部多人日常使用**：

1. 每人独立空间（自己的项目），必要时可协作
2. AI 费用**可看、可控、可限额**（当前一个 Key 全员共用，风险最高）
3. 关键操作**留痕可追溯**（谁改了稿、谁审的、谁导出的）
4. 管理员能管**用户、项目、用量**，并集中维护**节点库与提示词模板**
5. 对外访问**安全**（当前存在越权与开放注册问题）

## 2. 现状盘点（依据代码核实）

### 2.1 已具备

| 能力 | 说明 |
|---|---|
| 用户隔离 | `projects.owner_id` 归属字段；项目列表仅返回本人项目 |
| 全接口归属校验 | `_owned_project` / `_owned_node` 覆盖画布、节点、连线、稿件、审稿、执行、导出共 22 处 |
| 认证 | PBKDF2-SHA256（20 万次迭代）+ JWT（HS256，24h） |
| 画布协作基础 | WebSocket 节点状态推送、Revision 追溯链（parent_revision_id） |

### 2.2 缺口（按风险排序）

| # | 缺口 | 风险 | 影响 |
|---|---|---|---|
| 1 | **WebSocket 不校验项目归属**（仅验 token） | 🔴 高 | 任何登录用户知道 project_id 即可订阅他人项目的节点状态/报错流 |
| 2 | **注册完全开放** | 🔴 高 | 局域网内任何人可注册并消耗 DeepSeek 额度 |
| 3 | **无 AI 用量统计与配额** | 🔴 高 | 单人可用额度未知、无法限额、无法分摊成本 |
| 4 | 无角色体系（仅"所有者"） | 🟠 中 | 无法区分管理员/编辑/审核 |
| 5 | 项目不可共享 | 🟠 中 | 同事无法共同处理一个选题 |
| 6 | 无审计日志 | 🟠 中 | 操作无留痕，争议时无法追溯 |
| 7 | 节点库/提示词硬编码（前端数组 + 后端常量） | 🟡 低 | 管理后台**无法管理**，必须先数据化 |
| 8 | 无登录限流、无密码策略、无强制下线 | 🟠 中 | 弱口令与暴力尝试无防护 |
| 9 | 无数据库备份策略 | 🟠 中 | 数据丢失风险 |

## 3. 权限模型设计

### 3.1 角色定义

| 角色 | 标识 | 说明 |
|---|---|---|
| 系统管理员 | `admin` | 全部权限：用户、配额、模板、审计、所有项目 |
| 部门管理员（可选） | `manager` | 仅本部门用户与项目的管理权（**是否需要取决于是否引入"部门"层级**） |
| 编辑 | `editor` | 建项目、编辑画布与提示词、执行 AI 改写/转换、导出成稿 |
| 审核 | `reviewer` | 可审稿（通过/打回/批注）、可导出，不可改稿与执行 AI |
| 只读 | `viewer` | 仅查看画布与稿件 |

> 现有"项目所有者"概念保留，作为**项目级**授权（owner 拥有该项目全部操作权，与系统角色叠加）。

### 3.2 权限矩阵

| 功能 | admin | manager | editor | reviewer | viewer |
|---|---|---|---|---|---|
| 新建/删除项目 | ✓ / ✓ | 本部门 | 自建 / 仅自己 | ✗ | ✗ |
| 编辑画布、连线、提示词 | ✓ | 本部门 | 自己或受共享的项目 | ✗ | ✗ |
| 执行 AI 改写 / 转换 / 工具节点 | ✓ | 本部门 | ✓ | ✗ | ✗ |
| 审稿（通过 / 打回 / 批注） | ✓ | ✓ | ✗（默认自审回避） | ✓ | ✗ |
| AI 审稿节点 | ✓ | ✓ | ✓ | ✓ | ✗ |
| 成稿导出 / 复制 | ✓ | ✓ | ✓ | ✓ | 只读查看 |
| 用户 / 配额 / 模板管理 | ✓ | 本部门 | ✗ | ✗ | ✗ |
| 审计查询 | ✓ | 本部门 | 仅自己的记录 | 仅自己的 | ✗ |

### 3.3 数据模型变更（草案）

**users 表新增字段**

| 字段 | 类型 | 说明 |
|---|---|---|
| role | str(20) | admin / manager / editor / reviewer / viewer |
| is_active | bool | 禁用后不可登录（保留数据） |
| department_id | FK(optional) | 若引入部门层级 |
| created_by | FK(users) | 邀请人 / 管理员建号来源 |
| last_login_at | datetime | 最近登录 |
| token_version | int | +1 即强制下线该用户所有会话 |
| monthly_call_limit / monthly_char_limit | int | 个人配额（可空=继承全局） |

**新增表**

| 表 | 关键字段 | 用途 |
|---|---|---|
| `departments`（可选） | id, name | 部门层级 |
| `project_members` | project_id, user_id, role, created_at | 项目协作（共享给同事） |
| `invites` | code, role, department_id, created_by, expires_at, used_by, used_at | 邀请码 / 审批注册 |
| `audit_logs` | id, user_id, action, target_type, target_id, detail(JSONB), ip, created_at | 操作留痕 |
| `ai_usage` | id, user_id, project_id, node_id, kind, model, prompt_chars, output_chars, prompt_tokens, completion_tokens, cost_est, duration_ms, created_at | 用量与成本计量 |
| `quota_settings` | scope(user/department/global), ref_id, period(month), limits...(JSONB) | 配额策略 |
| `node_templates` | kind, subtype, label, icon, color, default_config(JSONB), prompt, scope(global/department/user), owner_id, enabled, sort | 节点库数据化（P2） |
| `prompt_templates` | key, name, content, scope, owner_id, version, enabled | 提示词模板库（P2） |

**迁移方式**：当前用启动时 `create_all` 建表；引入上述变更**建议改用 Alembic 正式迁移**（已有依赖），避免手工改表。

## 4. 成本与配额控制

### 4.1 计量口径
- 每次 AI 调用写入 `ai_usage`：**输入字数、输出字数、token（优先取 DeepSeek 返回的 usage 字段）、模型、耗时、估算费用**
- 计量点：改写、转换、工具（精简/风格）、AI 审稿 —— 全部统一走 `ai.py`，一处埋点即可

### 4.2 配额层级与默认值建议

| 层级 | 建议默认 | 超限行为 |
|---|---|---|
| 全局月度预算 | 由中心设定总额（如 300 元/月） | 达 100% 直接拦截 |
| 用户月度 | 600 次调用 / 约 100 万 token | 80% 提醒、100% 拦截 |
| 项目级（可选） | 单项目 200 次 | 拦截并提示 |

### 4.3 并发与限流
- 全局并发上限（建议 8）+ 单用户并发上限（建议 2）→ 防止一人刷满
- DeepSeek 429/超时：指数退避重试（最多 2 次）
- 前端复用现有节点 `running` 状态与 WebSocket 推送，显示"排队中"

### 4.4 可观测
后台"用量看板"：按天 / 按人 / 按项目的调用量与消耗排行、趋势图、预计月账单、CSV 导出。

## 5. 安全加固清单（P0）

1. **WebSocket 归属校验**（必做，当前可越权订阅）
2. **注册策略**：关闭公开注册 → 邀请码注册 / 管理员建号（内部推荐邀请码）
3. 登录失败限流（如 5 次/5 分钟）+ 失败审计
4. JWT 有效期缩短（8h）+ 刷新令牌；`token_version` 支持强制下线
5. 密码策略（≥8 位含字母数字）+ 管理员重置密码
6. **审计日志**：建/删项目、执行 AI、审稿、导出、登录、用户与配额变更
7. 数据库备份：每日 `pg_dump` + 保留 30 天 + 异地副本；`.env` 单独备份
8. **建议启用 HTTPS**：内网也建议（浏览器剪贴板 API 在非安全上下文可能受限；当前实测 http 下可用，但换浏览器/版本可能失效）

## 6. 管理后台（P1）功能与页面

| 页面 | 功能 |
|---|---|
| 概览 | 用户数、项目数、今日 AI 调用、今日消耗、异常告警（配额超限/失败率） |
| 用户管理 | 列表/搜索、角色分配、启用禁用、重置密码、配额调整、邀请码生成与作废 |
| 项目管理 | 全局项目列表（归属、节点数、稿件数、最近活动）、转移归属、删除（进回收站）、打包导出 |
| 用量看板 | 按用户/项目/天统计、趋势、Top 消耗、CSV 导出 |
| 审计查询 | 按人/时间/动作/目标筛选 |
| 模板管理（P2） | 节点模板与提示词模板 CRUD、可见范围、版本与启用开关 |
| 系统设置 | 注册开关、默认模型、默认提示词与严格模式、平台可见性、并发与配额默认值 |

**实现要点**
- 后端 `/api/admin/*` 统一 `require_role("admin")` 依赖；管理操作全部写审计
- 前端 `/admin` 独立路由与布局，仅管理员可见入口
- 危险操作二次确认 + 操作原因填写（写入审计）

## 7. 节点库与提示词数据化（P2）

**为什么必须做**：当前节点库写在前端 `PALETTE` 数组、提示词写在后端 `PROMPTS` 常量——管理后台**改不了**它们，改一次要发版。

**设计**
- 表：`node_templates`、`prompt_templates`（见 3.3）
- 前端启动时拉 `/api/templates`：**内置定义作兜底，数据库配置优先**（保证新部署可用）
- 用户级：可"另存为我的模板"（scope=user），个人可见
- 执行时提示词优先级：**节点 config.prompt > 我的模板 > 全站模板 > 内置常量**
- 好处：管理员改一次全站生效；可按部门下发不同风格规范；支持 A/B 对比提示词效果

## 8. 部署与架构建议

**当前形态（单机）**：Ubuntu + Nginx（80） + uvicorn（systemd，127.0.0.1:8000） + PostgreSQL 18

| 规模 | 建议 |
|---|---|
| ≤ 50 人 | 现状足够，补 P0 即可 |
| 50–200 人 | 加 Redis + 任务队列（ARQ/Celery）做 AI 排队；数据库连接池与备份 |
| > 200 人 / 多单位 | 拆分实例 + Redis pub/sub 广播 WS；或按单位分租户隔离 |

**立即建议**：HTTPS 证书、每日备份、日志轮转、简单探活告警（磁盘/进程/接口）。
**注意**：80 端口目前由系统 nginx 承载（我们的站点靠 `server_name YOUR_SERVER_IP` 匹配），若要上域名或 HTTPS，需要规划证书与 server 块。

## 10. 待决策问题（需要你拍板）

1. **是否需要"部门"层级**？（全中心共用一套项目，还是按部门分开、部门管理员各自管）
2. **注册方式**：邀请码 / 管理员建号 / 保留开放注册但需审批？
3. **配额口径与数值**：按调用次数还是字数？每人每月上限多少？全局月度预算多少？
4. **是否允许项目共享协作**？若需要，审核角色如何分配？
5. **是否要求"自审回避"**（作者不能审自己写的稿）？
6. **节点库与提示词**：全站统一由管理员维护，还是允许用户自建个人模板？
7. **是否提供 HTTPS 与域名**？（影响剪贴板 API、后续手机端访问）

## 附：本文结论摘要

- 用户隔离**已实现**，不需要重做
- **必须**先补 P0：其中 WebSocket 越权与开放注册是当前最紧迫的两项
- 管理后台**需要建**，但它的前提是节点库/提示词先数据化，否则"管理节点库"只能是改代码
- 建议顺序：P0（安全+配额）→ P1（管理后台）→ P2（模板数据化+协作）
